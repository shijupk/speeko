You are a senior game architect, senior Rust engineer, and product manager.

I want you to generate a complete Product Requirements Document (PRD) for a Rust game project with strong technical depth and implementation awareness.

## Product idea
I have already built an offline speech recognition engine in Rust. It can reliably recognize the following 10 words with very low latency:

- start
- stop
- open
- close
- up
- down
- left
- right
- yes
- no

I want to build a speech-controlled 2D game in Rust, inspired by Chrome Dino / endless runner style gameplay, but designed specifically for discrete voice commands instead of keyboard typing.

This should be a real product-oriented PRD, not just a casual feature list.

## Core concept
The game is voice-first, not keyboard-first.
The game should be designed around:
- discrete voice commands
- timing windows
- lane-based or action-based movement
- contextual interactions
- lightweight gameplay
- offline operation
- desktop-first MVP, with future path to smaller devices / embedded targets

## Main gameplay assumptions
The initial MVP should be a 2D endless runner / command-action game.

Use these example mappings unless you find a better product-oriented mapping:
- up -> jump
- down -> slide / duck
- left -> move left lane
- right -> move right lane
- stop -> freeze / brace / pause
- start -> begin / resume
- open -> open gate / activate route
- close -> close shield / barrier / hatch
- yes -> accept route / reward / choice
- no -> reject route / alternate choice

## Architecture expectations
The design should align with a Bevy ECS architecture and modular plugins, but the PRD should remain product-focused, not just engine-focused.

The system should conceptually separate:
- microphone capture
- speech recognition
- recognized word stream
- command mapping / debounce / cooldown
- gameplay state mutation
- UI feedback
- diagnostics

## Product constraints
- offline only
- no external APIs
- no cloud speech service
- no ready-made speech recognition library for the core recognition logic
- small vocabulary
- fast response
- low footprint
- maintainable Rust codebase
- architecture should be clean and extensible

## Writing style
- professional
- detailed
- structured
- practical
- implementation-aware
- suitable for a real GitHub project and technical design discussion
- avoid fluffy marketing language
- focus on clarity and product usefulness

## Output format
Produce the final answer as a polished markdown PRD.
Use clear headings.

Use tables where useful.
